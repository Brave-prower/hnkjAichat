# 「检索透明化面板」实施提示词（分步执行版）

> **功能目标**：点任意 AI 回答的「为什么这样答」，展开一个面板，完整展示这次问答的检索与决策过程——
> 每条候选片段的相似度分数条、是否过闸门、检索模式（语义/关键词）、闸门结论、耗时。
> 让 RAG 从黑盒变成白盒，答辩时是「方法创新性 + 可复现性」的最强演示。
>
> **用法**：按顺序复制执行，每条做完验证 + 单独 commit。若已完成反馈闭环 Prompt 1（V5 迁移），本组迁移从 V6 起编。

---

## Prompt 1 —— 后端：检索打分全量透出

```text
给校园 RAG 问答系统加「检索透明化」的第一步：让检索层把打分过程完整暴露出来。

现状：
- backend/src/main/java/com/hnkj/qa/ai/vector/JdbcCosineVectorStore.java 的
  similaritySearch 只返回过阈值的 Top-K；阈值与 TopK 来自 campus.qa.* 配置
- RagQaService#prepare 负责检索 + 闸门 + 拼提示词，同步/流式共用
- 命中结果已有 documentId/title/pageNumber/text/metadata

请完成：
1. 改造 JdbcCosineVectorStore#similaritySearch：全量打分后按分数倒序返回全部候选
   （不再在存储层过滤阈值），新增返回字段 score（余弦相似度，保留 4 位小数）。
   阈值过滤职责上移到 RagQaService——保持最终行为不变（仍取过阈值的 Top-K）
2. 新增 DTO ai/RetrievalTrace：
   - mode（semantic / keyword / keyword-fallback）
   - threshold、topK、costMs、embeddingBroken（熔断器状态）
   - gate（PASS / REJECT_ALL_BELOW_THRESHOLD）+ gateReason（一句人话）
   - candidates: List<TraceItem>{ chunkId, documentId, title, pageNumber,
     score, hit(是否过阈值), snippet(前80字) }——未过阈值也要在列表里，hit=false
3. RagQaService#prepare 构建 RetrievalTrace 并挂到返回对象上（同步/流式两条路都要有）
4. 现有问答行为回归验证：同样的提问，命中结果与改造前一致

约束：不改提示词；不改前端；余弦算法不动。
验收：日志或断点确认 trace 里能看到 hit=false 的低分候选。
完成后单独 commit：feat: 检索全量打分与 RetrievalTrace 快照
```

```text
约束：SSE 分帧一律用 SseEmitter.event().name().data()，禁止手工拼帧（历史踩坑）；
校验失败继续走 error 事件通道。
验收：curl -N 流式接口可见 trace 事件 JSON；同步接口响应含 trace。
完成后单独 commit：feat: SSE 新增 trace 事件与同步接口 trace 字段
```

## Prompt 3 —— 前端：透明化面板组件

```text
第三步：前端新增「为什么这样答」面板（Vue3 + Element Plus，沿用 --app-* 设计令牌）。

1. stores/chat.js：消息对象增加 trace 字段，流式解析器处理新事件 trace
2. 新建组件 components/RetrievalTracePanel.vue：
   - 顶部摘要条：检索模式徽标（语义检索=蓝 / 关键词兜底=橙）、耗时 xx ms、
     命中 N / 候选 M、闸门结论（PASS=绿 / REJECT=红 + gateReason）
   - 候选列表：每条一个片段卡片——标题+页码、snippet、横向分数条
     （宽度=score*100%，过阈值部分用主色填充、剩余灰色底，阈值位置画一条竖线刻度）、
     hit 标记（过阈值=「已命中」徽标 / 未过=灰色「未达阈值」）

4. 闸门 REJECT（未命中直接拒答）的回答也要能看到面板——此时面板本身就是
   「为什么拒答」的解释，重点展示全部候选的分数

约束：不引入新依赖；面板默认收起。
验收：提问后展开面板，能看到 3 条命中 + 若干未命中候选的分数条与阈值刻度。
```

## 这组提示词的设计说明（答辩可讲）

1. **分层暴露而非前端造假**：分数、阈值、闸门全部来自后端真实数据，前端只做可视化——可复现性无懈可击
2. **职责上移是关键一步**：阈值过滤从存储层上移到 Service，才能看到「未过阈值」的候选；Prompt 1 里明确要求「最终行为不变」，用回归验证锁住改动风险
3. **拒答也透明**：面板在 REJECT 场景反而最有价值——它把「为什么拒答」变成了教学演示
4. **协议演进有纪律**：SSE 事件协议从三段扩到四段，要求同步更新文档与 swagger，体现工程规范
